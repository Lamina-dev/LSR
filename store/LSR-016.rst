LSR 016 - Expr 构造与提升规范
================================================================================


基本信息
--------------------------------------------------------------------------------


- LSR 编号 016
- 标题 Expr 构造与提升规范
- 作者 Ziyang-Bai
- 状态 草案
- 类型 标准规范
- 创建日期 08-12-2026
- 归属项目 编译器、标准库、CAS

摘要
--------------------------------------------------------------------------------


定义 Lamina 中 ``Expr`` 的直接构造、普通值到 ``Expr`` 的提升边界、符号函数调用解析和 ``Expr`` 降级规则，以及 ``std.cas`` 的替换规则、结构匹配与重写接口。目标是让 ``x + 1``、``sin(x)``、``max(x, y, 0)`` 和 ``x => 2`` 等表达式在类型检查阶段有确定语义。

技术规范
--------------------------------------------------------------------------------


1. 范围
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


本规范定义 ``Expr`` 在 Lamina 类型系统和表达式构造阶段的行为，以及显式 CAS 代入、结构匹配和重写。

``Expr`` 是不可变符号表达式值。``Expr`` 可以表示数字、符号、函数调用、集合、区间和由 LSR-014 定义的数学运算符表达式 [1]_。区间的普通类型与命名构造函数由 LSR-017 定义 [4]_。

2. 符号声明
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``sym`` 声明创建 ``Expr`` 类型的符号值。

.. code-block:: text

   sym x
   sym y, z


- ``sym`` 声明的名称在当前作用域绑定为 ``Expr``
- 符号名称必须与声明标识符一致
- ``sym`` 不创建运行时可变变量
- 已有同名绑定时，``sym`` 必须按普通声明冲突规则报错

3. 直接构造
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


当表达式的期望类型为 ``Expr`` 时，允许从 Lamina 表达式直接构造 ``Expr``。

.. code-block:: text

   sym x
   let a Expr = x^2 + 1
   let b Expr = sin(x) + 1
   let c Expr = max(x, 0)


以下表达式可在 ``Expr`` 期望上下文中构造符号表达式：

- 整数、分数和有限小数字面量
- ``sym`` 产生的符号
- ``Expr`` 值
- 使用 LSR-014 中适用于符号表达式的算术、关系、逻辑和集合运算符组成的表达式 [1]_
- 函数调用
- 有限集合字面量和标准库区间构造调用
- 元组，前提是目标 ``Expr`` 构造规则支持元组表达式

4. 自动提升
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``Expr`` 自动提升只在表达式已经处于 ``Expr`` 上下文时发生。

.. code-block:: text

   sym x
   let a = x + 1      # Expr
   let b = 1 + 2      # num
   let c Expr = 1 + 2 # Expr


自动提升规则：

- 任一操作数类型为 ``Expr`` 时，适用于符号表达式的二元数学运算结果为 ``Expr``
- 正负号、逻辑非作用于 ``Expr`` 时，结果为 ``Expr``
- 目标类型显式为 ``Expr`` 时，按第 3 节允许的构造范围提升
- ``=>`` 的结果类型固定为 ``rule``，``===`` 的结果类型固定为 ``bool``
- ``is`` 执行普通对象同一性判断，``as`` 执行显式转换
- 集合目标类型为 ``set<Expr>`` 时，元素可提升为 ``Expr`` [2]_
- 普通全数值表达式不得因为语法形状自动提升为 ``Expr``

5. 不提升的情况
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


下列情况不得自动提升为 ``Expr``。

.. code-block:: text

   let a = 1 + 2
   let b = sin(pi / 2)
   let c = {1, 2, 3}


- 没有 ``Expr`` 操作数、``Expr`` 期望类型或 ``sym`` 参与的普通数值表达式
- 已解析为普通标准库函数调用且实参不含 ``Expr`` 的表达式
- ``bool``、``text``、``rule``、普通数组、普通矩阵和运行时对象
- 赋值、模块导入、控制流语句和副作用表达式

6. 函数调用解析
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


函数调用解析必须先执行普通名称解析，再决定是否构造符号函数调用。

解析顺序：

1. 若调用目标解析为普通函数，且实参类型满足该函数签名，则按普通函数调用处理
2. 若调用目标解析为普通函数，但任一实参为 ``Expr``，并且没有可用的普通 ``Expr`` 重载，则构造符号函数调用
3. 若调用目标未解析为普通函数，但当前上下文期望 ``Expr``，则构造未解释符号函数调用
4. 若调用目标未解析为普通函数，且当前上下文不期望 ``Expr``，则报未绑定名称错误

.. code-block:: text

   sym x
   let a = sin(pi / 2) # 普通函数调用
   let b = sin(x)      # Expr 符号函数调用
   let c Expr = f(x)   # 未解释符号函数调用
   let d = f(1)        # 未绑定名称错误


标准库可以为常用数学函数提供 ``Expr`` 重载。若存在普通 ``Expr`` 重载，调用该重载；若不存在，则按符号函数调用构造，不得静默降级为数值调用。

本规范第 10、11 节的 CAS 代入、匹配与重写属于执行接口，与 LSR-018 [5]_ 的终止函数采用相同的普通调用规则：调用时按声明的签名检查实参数量和类型，校验通过后执行对应操作，校验失败时直接诊断。

7. 集合、区间和元组
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


集合、区间和元组在 ``Expr`` 上下文中的构造规则如下。

.. code-block:: text

   sym x
   let roots set<Expr> = {-1, 1}
   let domain Expr = std.interval_closed_open(0, 1)
   let pair Expr = (x, x + 1)


- ``set<Expr>`` 期望上下文中，集合元素可逐个提升为 ``Expr`` [2]_
- ``Expr`` 期望上下文中，标准库区间构造调用产生区间表达式
- ``(a, b)`` 始终是元组；开区间写成 ``std.interval_open(a, b)`` [4]_
- 含 ``Expr`` 端点的区间构造符号区间表达式；普通端点构造 ``interval<T>``
- 元组是否可作为 ``Expr`` 节点由 CAS 支持域决定；不支持时必须报类型错误或不支持错误
- 无限集合、条件集和全集不由普通集合字面量自动构造

8. 比较与逻辑表达式
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``==``、``!=``、``<``、``<=``、``>``、``>=`` 作用于 ``Expr`` 时，构造类型为 ``Expr`` 的符号关系表达式。

.. code-block:: text

   sym x
   let a = x > 0          # Expr
   let b = x > 0 and x < 1 # Expr 条件表达式
   let c = 1 > 0          # bool


- 上述比较运算在全普通值上返回 ``bool``，含 ``Expr`` 时返回 ``Expr``
- ``===`` 接受两个 ``Expr`` 操作数，返回 ``bool``，按 LSR-007 执行有限证明 [3]_
- 含 ``Expr`` 的 ``and``、``or``、``not`` 构造符号逻辑表达式
- ``if`` 和 ``while`` 按核心语言规则接收 ``bool`` 条件；``Expr`` 条件按类型错误诊断。扩展语法若支持符号条件，须显式定义相应求值规则

9. CAS 替换规则
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``rule`` 是内建不可变的替换规则类型，类型写作 ``rule``。``lhs => rhs`` 保存左右两个 ``Expr``，由代入或重写函数显式应用。

- 两侧分别处于 ``Expr`` 期望上下文，按第 3 至 7 节的规则构造或提升
- 构造时按先左后右的顺序各求值一次；应用规则时直接读取已保存的两个 ``Expr``
- ``=>`` 使用固定二元形式；链式写法 ``a => b => c`` 产生语法错误，以 ``rule`` 作为任一操作数产生类型错误
- ``rule`` 可绑定名称、作为函数实参或返回值，也可存入 ``set<rule>``
- 两条规则的 ``==`` 返回 ``bool``：左侧和右侧分别结构相等时为 ``true``；``!=`` 为其取反
- ``set<rule>`` 以两侧表达式的结构相等关系去重
- ``table{...}`` 中的 ``=>`` 是表项键值分隔符，由表字面量语法解析为表项

本规范的结构相等按节点种类、运算符或函数名、实参数量及有序子节点逐项比较；符号按名称比较，数值常量按精确值比较。比较直接使用表达式的既有节点及子节点顺序，所需信息由结构本身完全确定。

.. code-block:: text

   import std.cas

   sym x, y
   let replacement rule = x => 2
   let replacements set<rule> = {replacement, y => 3, x => 2}
   # 去重后保留 x => 2 与 y => 3

   func replace(expr Expr, replacement rule) -> Expr {
       return cas.substitute(expr, replacement)
   }

   let a = replace(x + 1, x => 2) # 结构为 2 + 1 的 Expr


10. 代入
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``std.cas`` 导出以下普通函数：

.. code-block:: text

   func substitute(expr Expr, replacement rule) -> Expr
   func substitute(expr Expr, replacements set<rule>) -> Expr


单条规则等价于单元素规则集合。代入按源码顺序对所有实参各求值一次，再使用得到的表达式及规则值执行结构替换。

- 规则左侧与原表达式的当前整棵子树做结构比较，符号按名称匹配
- 当前节点命中规则时，以规则右侧作为该整棵子树的最终结果，并结束这棵子树的处理
- 当前节点与规则左侧存在结构差异时，按子节点原顺序递归处理；每个原节点至多访问一次
- 集合内所有规则同时作用于原表达式，规则选择由当前子树和规则左侧的结构相等关系确定
- 规则集校验在遍历前覆盖全部规则；相同左侧对应多个结构各异的右侧时，诊断 ``ExprConflictingRules``
- 空规则集或命中次数为零时返回原 ``Expr``；输入和规则值在调用前后保持一致
- 结果保留结构替换产生的表达式形态；后续数值求值和代数化简通过各自的显式接口执行

.. code-block:: text

   import std.cas

   sym x, y
   let a = cas.substitute(x + y, {x => y, y => 2}) # y + 2，同时代入原表达式
   let b = cas.substitute(x + 1, {(x + 1) => 9, x => 2}) # 9
   let c = cas.substitute(x + y, {x => 3, y => 4}) # 3 + 4
   let d = cas.substitute(x, {})                  # x
   # cas.substitute(x, {x => 1, x => 2})          # ExprConflictingRules


11. 数学模式匹配与重写
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``std.cas`` 导出以下普通函数。模式本身是 ``Expr``，使用相同的表达式构造语法。

.. code-block:: text

   func match_expr(expr Expr, pattern Expr, variables set<Expr>) -> table<text, Expr>?
   func rewrite(expr Expr, replacement rule, variables set<Expr>) -> Expr


11.1 模式变量与匹配
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^


- ``variables`` 显式列出由 ``sym`` 产生的符号值；每项必须出现在 ``pattern`` 中，重写时必须出现在规则左侧
- 集合中的符号是模式变量，可捕获一棵完整的 ``Expr`` 子树；其余符号按名称作字面结构匹配
- 同一模式变量重复出现时，每次捕获的子树必须结构相等；捕获值保存在结果表中，符号声明及其原有绑定保持原值
- 其余节点按第 9 节的结构相等规则递归匹配；算术、幂和函数调用节点必须受支持
- 匹配按表达式既有节点顺序逐项进行，数值常量采用精确值比较
- 实参按源码顺序各求值一次，再检查类型、支持域和模式变量集合；非法变量集合诊断 ``ExprInvalidPatternVariables``

``match_expr`` 将整个输入 ``Expr`` 与完整模式进行一次结构匹配，结果按以下规则返回：

- 匹配成功：返回完整捕获表，键集合恰好对应 ``variables`` 中的所有符号名，值为各符号捕获的 ``Expr``
- ``variables`` 为空且匹配成功：返回空捕获表
- 结构匹配失败：返回 ``null``
- 类型冲突、节点超出支持域或求值失败：按第 13 节的错误路径传播

.. code-block:: text

   import std.cas

   sym x, y, base, exponent, u
   let powers = cas.match_expr(x^2, base^exponent, {base, exponent})
   # 成功：键 "base" 对应 Expr 符号 x，键 "exponent" 对应 Expr 常量 2
   let repeated = cas.match_expr(x + x, u + u, {u}) # "u" 对应 x
   let different = cas.match_expr(x + y, u + u, {u}) # null
   let literal = cas.match_expr(y^2, x^2, {})        # null
   let exact = cas.match_expr(x^2, x^2, {})          # 空捕获表
   let whole = cas.match_expr(x^2 + 1, base^exponent, {base, exponent}) # null


11.2 捕获值重写
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^


``rewrite`` 先求值各实参一次并检查规则及模式变量，再按原表达式节点制定一次左到右、从子节点到父节点的遍历。子节点处理完成后，用处理后的子节点组成当前节点，再尝试匹配规则左侧。

- 命中时，使用该次匹配的完整捕获表，同时替换规则右侧对应的模式变量，所得 ``Expr`` 作为当前节点的结果
- 右侧中属于 ``variables`` 的符号按左侧捕获值替换，其余符号保持普通 ``Expr`` 字面含义
- 替换直接使用规则已保存的右侧 ``Expr``；每个捕获值作为整体子树插入并保留自身内部结构
- 匹配失败时保留当前节点及已处理的子节点；命中次数为零时返回原表达式
- 遍历计划覆盖原表达式各节点，每个原节点尝试一次，计划完成即返回结果。插入值作为该节点的最终结果，父节点可匹配包含子节点重写结果的结构
- 输入及规则在调用前后保持原值；操作成功时返回完整结果，错误通过普通调用的错误路径传播

.. code-block:: text

   import std.cas
   use std.math.{sin, cos}

   sym x, y, u
   let a = cas.rewrite(sin(x), sin(u) => cos(u), {u}) # cos(x)
   let b = cas.rewrite(sin(x + 1), sin(u) => u^2, {u}) # (x + 1)^2
   let c = cas.rewrite(sin(x), sin(u) => u + y, {u}) # x + y，y 是字面符号
   let d = cas.rewrite(sin(sin(x)), sin(u) => u + 1, {u}) # (x + 1) + 1
   let e = cas.rewrite(sin(x), sin(u) => sin(sin(u)), {u}) # sin(sin(x))，插入值保持原状


12. 显式求值与查询
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


``Expr`` 到 ``num``、``bool``、``text`` 或普通容器的转换，必须通过声明了目标返回类型的显式接口完成。

允许的显式入口：

- 用 ``substitute`` 代入后，再调用数值求值函数
- ``evalf`` 或等价的显式近似求值函数
- ``===`` 数学等价判定 [3]_
- ``match_expr`` 或其他明确声明返回类型的 CAS 查询接口

.. code-block:: text

   import std.cas

   sym x
   let expr = x + 1
   let a = evalf(cas.substitute(expr, x => 2))


普通数学函数直接返回声明类型的结果。求值接口校验所需符号的取值绑定、表达式支持域和结果完整性；校验失败时必须给出诊断，并沿 LSR-018 的错误路径传播 [5]_。

求解接口证明解集为空时返回空 ``set<Expr>``；``match_expr`` 通过 ``null`` 表示结构匹配失败；``===`` 返回当前规则与预算下的证明结果，其语义遵循 LSR-007。

13. 错误
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~


实现至少应区分下列错误：

- ``ExprUnboundName``：非 ``Expr`` 上下文中调用未绑定函数或变量
- ``ExprTypeMismatch``：无法把表达式提升为目标 ``Expr`` 形态
- ``ExprUnsupportedNode``：CAS 不支持对应表达式节点
- ``ExprAmbiguousSyntax``：调用、索引或其他表达式形态仍无法由语法规则消歧
- ``ExprImplicitDowngrade``：试图把 ``Expr`` 隐式用作普通值
- ``ExprConflictingRules``：同时代入的规则具有相同左侧和不同右侧
- ``ExprInvalidPatternVariables``：成员的节点种类或出现位置违反第 11.1 节的模式变量要求

类型和语法错误在编译时可确定时必须直接诊断。运行时数学错误使用 LSR-018 的 ``MathError`` 和 ``raise`` 传播，虚拟机故障沿同一规范的故障路径传播 [5]_。错误名称可以映射到统一错误系统，并保留各错误类别的独立语义。
